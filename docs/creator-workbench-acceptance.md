## 对抗审查闭环

| 风险 | 已落实的处理 |
|---|---|
| 预览读取未导入的本机文件 | 工作台限制素材根；CLI只处理实际图片节点；代码块、行内代码和惰性子树不触发读取 |
| 图片错误匹配或损坏 | 明确目录冲突拒绝；结构、CRC、尺寸与离线真实解码检查；原图字节保留 |
| 预览、保存及发布模板不同 | 文章级模板状态、包含模板的缓存键、原子保存及不可变投递快照 |
| 旧响应覆盖新输入 | 正文版本、模板与请求身份校验，晚到的旧结果不采用 |
| 采集入口和关键词误过滤 | 空链接采用默认来源，领域描述交给分析，不当整句硬过滤 |
| 证据丢失或造假 | 保留原生条目ID；引用必须来自本次采集；无数据或模型失败不回退示例 |
| 飞书列表图片被当代码 | Markdown语法识别，导出后检查图片数量、顺序及已下载素材对应关系 |
| 采用选题覆盖旧计划 | 已有题目、资料或关联文章的日期返回409，保留原记录 |
| CDP端口复用导致串号 | 会话记录并强制核对浏览器实例身份，旧port-only记录拒绝；不连接其他浏览器 |
| 登录弹窗背后的内容误算成功 | 结合弹窗容器、表单和按钮识别登录/注册；普通导航登录按钮不误阻断 |
| 失效会话无法重新连接 | 服务端失效并删除缓存，前端清pending及更新状态，保留“重新连接”入口 |
| 模型接收到访问参数 | 分析输入去除访问、跟踪参数和hash；保留必要文章身份，原访问链接仅留本地 |

复审使用隔离文件、数据库、DOM和CDP探针，没有操作真实平台账号。最终结论：在本轮审查范围内未发现仍未处理的阻断项。

## 用户验收顺序

1. 刷新工作台，在内容中心打开新的“飞书导入”FDE文章。向下滚动，确认三张配图清楚且位置正确。
2. 修改一处正文，先不保存，切到“平台预览”检查“未保存编辑预览”，再回“编辑正文”确认没有丢稿。需要保留时再保存，不执行发布。
3. 选一个公众号模板，或点击随机模板；检查标题与段落。切到知乎再保存，再回公众号，所选模板不应被撤回。摘要可以留空。
4. 用含表格的稿件切到人人都是产品经理；编辑正文里仍是表格，预览里应是分段图片，最后一行不能丢。
5. 打开“选题计划”，检查当前来源覆盖和4张真实分析卡。采用到空闲日期；若日期已有内容，应被阻止而非覆盖。
6. 需要验证三个受限平台时，在“平台登录”中正常登录或重新连接，并保留登录窗口；然后重新采集。需验证码时自行完成，不要求系统绕过。
