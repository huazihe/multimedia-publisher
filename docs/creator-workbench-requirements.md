# 创作者工作台：需求与实现方案

## 产品目标

让创作者维护一份原稿，在同一工作台中导入图文、编辑预览、处理平台格式、选择投递入口；减少反复找网站、导出、复制粘贴、扫码和修图片格式的劳动。

发布适配只处理格式、排版、图片和必要字段，不按平台读者重写文章，不替换作者观点。选题分析是另一项独立能力：观察真实信息源，提出可写的主题；用户采用后进入计划，不自动写全文或发布。

## 保留的核心目的

- 飞书继续作为熟悉的写作入口。给定文档链接，自动导出 Markdown 和原图到本地，再送入工作台，不需要为此重建一套重型云端编辑器。
- 同时支持本地 Markdown、HTML、TXT，以及配套图片；保留图片在正文中的位置。
- 编辑正文与平台预览采用 Tab 切换，各占完整画布；切换保留未保存编辑，不触发保存。导航与文章列表可单独收起，窄屏自适应。
- 公众号保留已有40个模板文件，按实际样式命名；14个完全重复副本在下拉框合并为26种风格，不改原文件名或旧文章关联。工作台保持中性配色，平台图标保留品牌原色。
- 人人都是产品经理等平台的特殊格式在派生稿里处理，原稿不被平台限制污染。
- 复用既有账号连接和会话机制，减少重复登录；不承诺会话永久有效。
- 从八个常用平台的热点或内容线索找选题，帮助作者决定写什么；不扩展到小众平台，不用虚构数据填补采集失败。

展示优先级：公众号 → 人人都是产品经理 → 少数派 → 小红书 → 优设 → 抖音，前六个不变。其余按通用文章、技术知识、本地工具分组，不再把工业/B2B及其他垂直门户铺在常用列表里。

当前常用目录由`publisher-dashboard/platform-catalog.js`统一维护：16个通用平台（前六个，以及知乎、今日头条、百家号、搜狐号、企鹅号、微博、B站、简书、网易号、豆瓣）、4个技术/知识平台（掘金、CSDN、语雀、博客园）、1个本地ZIP导出工具。技术组默认折叠，已选中该组平台时展开。本地导出明确不对外发布。

中国机器视觉网、北极星社区、电子发烧友、电子工程专辑、电子工程世界、中国自动化网、八方资源网、阿仪网、黄页88、搜了网，以及财经和其他较专门的开发社区退出常用目录。底层适配器、平台记录、登录资料和历史任务保留；新任务不能向非活动目录平台投递，历史仍可查看/核对。自动登录检查不再请求这些入口。

新增简书、网易号仅提供已核验的官方登录/写作后台入口与本地预览，不自动草稿、上传或发布；能力明确标注为手工操作，不能把无法自动核验登录说成官网未登录。选题雷达维持已有八个平台，不扩大采集或改动已生成选题。

## 首期范围

| 模块 | 功能约定 | 完成标准 |
|---|---|---|
| 飞书导入 | 输入 HTTPS docx/wiki 链接；解析实际文档类型；通过固定 user profile 只读导出全文和配图 | 文本完整、图片下载成功、位置对应；权限不足或内容不完整时停止 |
| 本地图文导入 | 正文和图片一起选择；按路径匹配；图片去重存储 | 中文路径有效；明确目录不匹配和重名时拒绝；损坏图片不得标为成功 |
| 公众号排版 | 保留并安全内联头部 CSS；修复隐藏标题、长标题窄竖排；保存选择的模板 | 40 套真实稿件回归；正文、图位、标题与平台预览一致 |
| 实时预览 | 输入变化后延迟合并请求；正文版本和模板共同决定请求身份 | 旧响应不能覆盖新内容；预览不保存正文、不发布 |
| 保存与投递一致 | 保存时原子保存正文及明确选择的模板；投递使用对应版本的不可变快照 | 未保存预览不能在保存后静默变成无模板正文 |
| 表格转图 | 只在人人都是产品经理派生稿转换；重复表头、无损分段、缓存 | 原稿表格仍在；长表末行完整；过大或不可拆分时明确失败 |
| 图片可靠性 | 解码、类型、大小、尺寸及路径检查；CLI 只接收已导入的本地资源 | 不读取素材根外文件；上传失败不能回退原链接冒充成功 |
| 选题雷达 | 八个常用平台共用一套选题 Skill；资料与模型分析分别记状态 | 每张卡能回查证据；无资料不出假热点，模型失败保留已采集资料 |
| 采用到计划 | 用户选择候选与日期后采用 | 已有选题、资料或关联文章的日期返回冲突，不静默覆盖 |
| 验收 | 自动回归、真实浏览器、对抗性审查、用户验收 | 分清代码实现、隔离通过、当前账号实测和未覆盖范围 |

本轮实现与验收不包含真实对外投递、飞书云端写入、修改账号权限或密钥、安装全局依赖、数据库迁移、Git提交/推送。常用目录为20个文章平台＋1个本地工具；底层37个入口保留兼容，不代表37个平台可自动发文。

## 飞书到工作台

流程：指定文档链接 → 解析 wiki/docx → 读取全文 → 下载原图 → 保存 original.md 和 assets → 校验图片 → 导入内容中心。

原始导出包保留相对图片路径，工作台正文引用本机素材库，CLI 的平台快照内嵌图片字节。原始 Markdown、飞书文档和平台派生稿分开，避免修一个平台时改变原稿。

当前实现使用本机 lark-cli，默认 misshe-personal / user；不依赖全局默认账号，不自动切 Bot 或补权限。飞书返回非 docx、截断/分页信号、无法下载图片等情况时明确报错，不导入不完整内容。附件和画板不冒充普通配图。

本地配图限制为40张、单张8 MiB、合计24 MiB；只支持PNG/JPEG/GIF/WebP，需通过结构、尺寸和真实解码检查。代码示例不当成图片下载指令；未知或权限保护的图片不能作为“已完整本地化”放过。

私有验收使用了一篇含三张1672×941图片的授权文档。公开仓库不包含该文档链接、文章原文及配图；请用自己的授权文档复测。导出时仅替换图片地址，其他正文保持一致。

## 公众号与平台格式

已有40个公众号模板文件继续使用，对应26种独立风格。命名记录在`skills/weixin-layout/template-catalog.json`；名称描述配色、版式与适合的文章类型。同款合并只影响选择界面。格式转换先保留完整文档的安全CSS再内联，不能先截取body导致样式丢失。生成采用静态样式；外部CSS、资源型CSS和动画不保留，不声称微信客户端已完整验收。

长标题按容器正常换行，不能选择SVG中的隐藏文字作为唯一标题。摘要可留空，不强制重复截取开头，也不引入AI改写。

人人都是产品经理的表格在派生层离线渲染为PNG。正文母稿不改；派生图片经同一素材边界内嵌到CLI快照。长表按安全行边界分段，表头重复，合并单元格不能被裁断。图片预检、下载、上传任一失败时中止本次草稿创建，返回可定位且脱敏的错误。

## 常用平台共用选题 Skill

维护入口：`skills/platform-topic-scout/SKILL.md`。方法来源是本机 `xiaopu-writing/references/topic-evidence.md` 已吸收的公众号选题能力，不修改原个人写作Skill，不复制个人IP素材。

共用逻辑：真实来源 → 同事件归并 → 读者问题 → 作者接近性 → 原创切入点 → 读者收益 → 证据缺口。

| 平台 | 观察对象 | 口径 |
|---|---|---|
| 抖音 | 可访问的官方热榜/热点条目 | 保留原生条目ID，不因共同热榜URL丢掉不同热点 |
| 小红书 | 可访问内容列表、推荐流或指定笔记 | 推荐流不代表全平台热榜；登录/动态渲染受限时说明 |
| 今日头条 | 官方热门榜条目 | 保留榜单与原始指标，不与其他平台混算 |
| 知乎 | 官方热榜或指定问题 | 401、登录墙、验证码不绕过 |
| 人人都是产品经理 | 近期产品/AI文章列表与可见信号 | 首页局部内容不能声称全站最热 |
| 公众号 | 小普写作Skill的多源选题雷达 | 不需要额外提供公众号名单，也不冒充公众号原生热榜 |
| 少数派 | 公开首页、精选/近期列表和官方RSS/Atom | 仅作内容信号，不是全站热榜，不计算精选概率 |

公众号雷达参考AIbase、人人都是产品经理、少数派、Simon Willison、Import AI、Latent.Space。它们分别提供事件、产品讨论、工具尝鲜、工程实践、研究及访谈线索；每次保存实际覆盖和失败来源。少数派同时作为独立选题观察平台，复用同一套证据约束；同站同条内容不能重复算作独立证据。

标题或列表摘要只算线索，不能声称读了正文；发布日期未知不能用采集时间代替。热度排名、播放、点赞、收藏、阅读数保留原名，不相加成统一热度分数，也不预测上精选概率。同站重复报道不当成独立证据。

关注领域由模型理解，不以整句字符串硬过滤来源。分析阶段使用本机Codex，读取共用Skill和本次规范化资料，禁用shell、应用、hooks等工具，输出受JSON Schema和证据ID校验约束的选题卡。没有证据、分析失败或超时，必须保留限制，不返回固定示例。

每张选题卡包含：主题、建议平台、读者问题、切入点、为什么现在、读者收益、来源ID、缺失证据与事实风险。平台建议只是适合的呈现方向，不等于该平台已经采集到热度证据。

## 用户验收路径

恢复策略（2026-09-06）：

- 去掉仅改变前端显示的三个虚拟员工角色。折叠菜单采用图标按钮，位于桌面侧栏底部；折叠为窄栏后仍可展开。手机上按钮保留在菜单栏右上角，不跟随菜单一起隐藏。
- 发布待核对、发布进行中与正文版本冲突使用独立错误码，不能将全部409都标成“文章在其他标签页修改”，也不叠加错误提示形成无法保存的循环。
- “恢复工作”只读检查已存原稿、平台会话和该平台最新任务。关闭窗口可沿原profile重开；原标签页存在时激活并复用，不导航、清空或重复填稿。
- 已有草稿/发布的明确回执时打开原链接或平台后台，不再创建同一份；没有回执时不能因关窗就认定未提交。
- 人工明确确认“未保存草稿且未发布”后，只解除这一任务、这一平台的重试限制，保留原始回执和声明审计。原operationId不可重用，其他平台继续锁定；确认本身不投递。恢复入口的重新准备只进入draft确认，不直接公开。
- 真正的版本冲突先保留本页编辑为恢复副本，再载入最新稿；副本保存失败时留在当前页。相同内容不生成多余副本，默认选中的模板不当作用户修改。

真实任务的人工确认由用户在工作台执行；实现和测试不得替用户解除现有小红书、公众号的待核对记录。

1. 刷新 http://127.0.0.1:18810 ，在内容中心打开已导入的飞书FDE文章，核对三张配图。
2. 修改一处正文但先不保存，切到“平台预览”确认效果，再回“编辑正文”确认文字仍在；保存是独立操作。
3. 切换公众号模板生成排版，检查标题、小标题、段落和图片；摘要可清空。
4. 使用带表格的稿件切换人人都是产品经理，确认预览中为表格图片、编辑正文中母稿仍为表格。
5. 进入选题计划，查看八个平台入口和每次任务的实际覆盖。首轮26条来源与4张卡片不因新增平台而自动扩充；采用不会自动生成正文或发布。
6. 受限平台需要正常登录或可访问来源后再验证；平台最终草稿/公开发布不是本次验收范围。

## 优设与阅读预览

优设已接入登录配置、只读身份核验、本地阅读预览及官方手工投稿入口；它通过文章/飞书文档和配图链接送审，不自动保存草稿、上传或公开发布。默认观察 `/archives` 公开列表，已实采10条标题线索；不把相对时间推算为精确日期或将列表位置当热度排名。复用现有选题Skill，不覆盖原26条资料与4张卡片。详见[优设接入说明](uisdc-integration.md)。

人人和优设预览中的图片等比限制在正文范围；人人适配HTML也附带该约束。原图字节、正文与公众号模板不变。草稿准备和人工核对入口位于预览上方，不提供自动公开发表按钮。

## 后续边界

优先平台能力的实现与实号验收必须分开，详见[平台能力矩阵](platform-capabilities.md)。公众号、人人都是产品经理、少数派仅开放草稿，不伪装直发；前两者封面仍需在平台设置。小红书仅填写编辑页，不代表云端草稿成功；抖音仅支持纯文字正文，带内嵌图片的文章阻止提交。缺少明确回执均为“待核对”，同一内容不能靠重复保存、更换模板或换操作ID绕过防重试。

2026-09-07 起，发布中心只提供“同步草稿 / 准备内容”，最终发表由作者在平台完成。公众号、人人都是产品经理、少数派均可一起勾选；元数据区分草稿、纯文字草稿、仅编辑器、手工、导出，不再用同一个“已成功投稿”描述。前端无自动发表入口，后台拒绝所有 `direct` 请求（先于认证、素材处理和任务创建），缺省模式为 `draft`。原有公开发表历史不删除。编辑器准备即使旧适配器报成功，也保留待核对状态；本地导出不计为平台草稿或公开发表。

同步后按文章和平台匹配最近一次结果，提供“检查草稿并发表”或“去平台核对”入口，只打开对应页面，不再上传、覆盖平台编辑或点击发表。公众号终审包括是否开启群发通知；不通知的发表也属于公开。取消确认不产生任务，执行期间相关操作锁定，结果不确定时继续防重试。
