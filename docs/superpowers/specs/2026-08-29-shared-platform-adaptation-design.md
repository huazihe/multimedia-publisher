# 多平台内容导入、适配预览与发布闭环设计

## 目标

把当前项目从“面板生成示例正文 + CLI 发布文件”升级为统一内容工作台：用户可以导入或粘贴一篇文章，在本地内容中心维护母稿，预览各平台真正会使用的适配结果，再按平台保存草稿或直接发布。

完成后应满足：

1. 支持粘贴 Markdown、HTML、纯文本，以及上传 `.md`、`.html`、`.txt` 文件。
2. 导入内容进入现有 `contents` 表并可继续编辑，不建立第二套内容仓库。
3. 面板预览和 CLI 发布调用同一套平台适配函数。
4. 微信公众号排版可以选择现有 40 套模板，不再只生成固定“清爽运营稿”。
5. 每个平台都能单独预览、保存草稿或直接发布；批量发布入口继续保留。
6. 不修改数据库结构，不读取或展示 Cookie 原文，不在预览阶段产生外部写入。

## 核心判断

项目最大的遗漏不是少了一个“导入”按钮，而是缺少“统一母稿到平台派生稿”的中间层。

当前数据流分成两条：

```text
本地文件 → CLI → 平台

选题/示例 → 面板 contents → 临时 Markdown → CLI → 平台
```

`contents.body` 是唯一母稿，但平台适配配置只停留在 adapter 声明中，CLI 没有在发布前统一执行。面板也无法查看最终平台正文。因此导入、平台预览、格式校验和实际发布结果彼此割裂。

正确的数据流应为：

```text
粘贴/文件/面板生成
        ↓
统一母稿（contents）
        ↓
共享适配层 prepareArticleForPlatform()
        ↓
平台派生稿（只读预览）
        ↓
单平台草稿 / 单平台直发 / 多平台批量发布
```

## 交互设计

界面采用“内容中心主导、编辑与预览并列”的模式：

- 参考 Contentful：左侧编辑、右侧实时预览，切换桌面与移动宽度时不离开当前文章。
- 参考 Buffer：先维护统一母稿，再选择平台查看各平台独立结果。
- 参考 Ghost：预览与发布动作放在文章编辑区域的固定工具栏中，发布前保持明确确认。

### 内容导入

内容中心页头增加“导入文章”。弹窗包含两个入口：

- “粘贴内容”：标题可留空，正文支持 Markdown、HTML、纯文本。
- “选择文件”：浏览器使用 `FileReader` 本地读取 `.md`、`.html`、`.txt`，不把原文件上传到服务器。

识别规则：

1. 用户填写标题时优先使用用户标题。
2. Markdown 优先取首个一级标题。
3. HTML 优先取 `<title>`，其次取首个 `<h1>`。
4. 纯文本优先取第一行非空文本。
5. 无法识别时使用文件名或“未命名文章”。

导入完成后立即选中新内容，状态为“已导入”。

### 内容编辑与平台预览

文章详情使用双栏工作区：

- 左侧：母稿编辑器和保存状态。
- 右侧：平台适配预览。

右侧顶部包含：

- 平台下拉选择器；
- 输出格式标签（HTML / Markdown / 纯文本）；
- 桌面/手机预览切换；
- 适配提示，如标题长度、图片数量、链接清理、表格降级、发布时上传图片。

预览内容只来自共享适配层，不允许前端自行复制一套转换规则。

### 微信公众号模板

平台选择为微信公众号时额外显示：

- 40 套模板下拉选择器；
- “随机换一套”；
- “生成公众号排版”；
- “打开完整 HTML”。

模板渲染规则：

1. 保留原模板 `<head>`、CSS、外层结构和视觉主题。
2. 替换首个主标题、导语、正文内容与公众号尾部信息。
3. 清空模板示例正文，避免残留“此处为”“替换为”等说明。
4. 在成品根节点写入 `data-wechat-template`，用于回显模板名，不新增数据库字段。
5. 结构无法识别的模板返回明确错误并回退到通用排版，不输出半成品。

现有 40 套模板缺少统一 slot 标记，这是模板能力此前难以接入面板的直接原因。实现时增加统一渲染约定，而不是为 40 套模板写 40 段特例代码。

### 分别发布

平台预览底部提供：

- “保存该平台草稿”；
- “直接发布该平台”。

直接发布前显示确认对话框，明确平台、文章标题和动作。预览和保存母稿不触发外部平台。

发布中心继续支持多选平台批量发布。单平台和批量发布都必须先调用共享适配层，再把同一份派生稿交给 adapter。

## 共享适配层

在 core 包新增独立模块，公开以下接口：

```ts
prepareArticleForPlatform(article, platformId): PlatformPreparedArticle
```

返回结构至少包含：

```ts
interface PlatformPreparedArticle {
  platform: string
  title: string
  format: 'html' | 'markdown' | 'text'
  content: string
  htmlPreview: string
  imageCount: number
  warnings: string[]
}
```

适配步骤：

1. 从母稿同时构建规范化 HTML 与 Markdown。
2. 读取 adapter 的 `preprocessConfig`。
3. 执行链接、iframe、特殊标签、代码块、懒加载图片、空元素、section、表格等规则。
4. 应用平台明确要求：例如抖音/头条/小红书纯文本化，小红书图片上限，微信外链清理。
5. 生成安全的本地 HTML 预览。
6. CLI 发布时把同一份适配结果转换回 `Article` 后交给 adapter。

网络上传后的平台图片地址、平台草稿 ID 等只能在真正发布时取得，预览中应显示提示，不伪造最终地址。

## 后端接口

新增：

```text
POST /api/content/import
GET  /api/layout-templates
POST /api/content/:id/layout          body: { template }
GET  /api/content/:id/platform-preview?platform=...
POST /api/content/:id/publish-platform body: { platform, publishMode }
```

保留现有 `/api/publish` 作为批量发布接口。

接口错误必须区分：内容不存在、平台不存在、模板不存在、适配失败、未登录、平台发布失败。

## 数据与可追溯性

- 不新增数据库表或字段。
- 导入正文继续使用 `contents.body`。
- 公众号模板名写入 `layout_html` 根节点属性。
- 每次发布使用包含 job ID 的独立 Markdown 快照文件，避免同一内容重复发布时覆盖旧快照。
- `publish_jobs` 与 `publish_results` 继续记录平台级结果。
- 平台预览是可重复计算的派生结果，不写入数据库。

## 安全边界

- 文件导入仅在浏览器读取文本，限制扩展名和大小。
- HTML 预览禁止执行脚本、事件属性和危险协议。
- 模板路径只允许来自 `skills/weixin-layout/templates/`，禁止路径穿越。
- 直接发布必须二次确认。
- 测试只使用隔离数据库和本地导出平台，不向真实平台写入。

## 测试与验收

### 自动测试

1. 导入 Markdown、HTML、纯文本后标题和正文正确。
2. 非法扩展名、空正文、超大文件被拒绝。
3. 公众号模板列表为 40 套，非法模板名被拒绝。
4. 模板成品不残留占位提示，并包含真实标题与正文。
5. HTML、Markdown、纯文本三类平台预览符合各自规则。
6. CLI dry-run 和面板平台预览产生相同适配正文。
7. 单平台草稿只生成一个平台结果，不影响其他平台。
8. 原有 dashboard 测试、build、typecheck 全部通过。

### 浏览器验收

1. 粘贴文章导入后立即出现在内容中心。
2. 上传 `.md`、`.html`、`.txt` 均可导入。
3. 切换微信公众号、知乎、掘金、小红书、头条时预览结果明显变化。
4. 微信公众号可切换模板并打开完整 HTML。
5. 桌面端双栏清晰；手机端改为上下布局且无横向溢出。
6. 发布按钮、草稿按钮和批量发布入口层级明确。

## 不在本次范围

- 不调用大模型改写各平台文案。
- 不新增定时发布和审核流。
- 不迁移数据库结构。
- 不承诺 33 个平台全部完成真实直发；平台真实发布能力仍以 adapter 和当前登录状态为准。
