# 多平台内容发布工作台对抗式加固设计

## 目标

在不修改 SQLite 表结构、不迁移现有数据、不触发真实平台发布的前提下，修复对抗式审查确认的内容覆盖、排版与发布不一致、误发布、异常任务悬挂、导入内容触发本地 API、内容序列化丢失、输入失控、平台适配口径失真、品牌硬编码和缺少持续集成等问题。

完成后必须满足：用户导入或编辑一篇标准母稿，可以得到与实际发布输入一致的平台预览；公众号模板进入微信公众号发布快照；多标签页不会静默覆盖；批量直接发布必须再次确认；异常发布有可理解的终态；未受信任文章不能借资源标签调用本地 API；33 个平台都有明确、诚实、可维护的适配档案。

## 已确认边界

- 不新增、删除或修改数据库字段，不执行数据库迁移。
- 现有文章、选题、发布历史和登录文件保持原位。
- 不在自动测试中调用真实平台发布、登录或 Cookie 导出。
- 不伪造无法从当前适配器或权威资料确认的平台限制。
- 产品对外名称统一为“多平台内容发布工作台”；`@weibot/*` 包作用域和 `WEIBOT_*` 环境变量作为兼容接口暂时保留，但不再作为产品品牌展示。
- 当前功能分支和 PR #1 继续作为交付分支。

## 总体架构

系统继续使用一份标准母稿作为事实真源，但将“母稿版本”“平台发布源”“发布操作”三类状态分开处理：

1. 母稿通过现有 `updated_at` 充当乐观锁版本，不增加数据库字段。
2. 公众号排版 HTML 内嵌模板名和母稿 SHA-256，作为可验证的派生物；母稿变化后立即清空旧排版。
3. 每个平台在预览和发布时都从同一个平台发布源构造器取输入，避免预览一套、发布另一套。
4. 发布任务逐平台落库；发生不确定异常时，任务进入 `uncertain` 终态而不是永久 `running`。
5. 平台规则集中在显式档案中；已核验规则严格执行，未核验规则明确标为基础适配并要求人工确认。

## 一、母稿并发与派生排版

### 乐观锁

前端保存正文时必须提交当前内容的 `expectedUpdatedAt`。服务端使用现有 `updated_at` 比较版本：

- 相等：执行更新，并生成严格晚于旧值的新时间戳；
- 不相等：返回 HTTP 409 和最新内容摘要，不覆盖数据库；
- 未提交：仅内部兼容调用允许，浏览器 API 请求拒绝。

前端收到 409 后保留编辑器中的未保存内容，显示“文章已在其他标签页更新”，提供“重新载入最新版本”提示，不自动重试。

编辑器只在真实 `input` 事件发生时标记脏状态，聚焦输入框不得触发自动保存。

### 排版失效

只要标题、摘要、正文或内容类型发生变化：

- 清空 `layout_html`；
- 将有选题来源的内容恢复为“正文已生成”，导入内容恢复为“已导入”；
- 清除前端平台预览缓存；
- 完整 HTML 预览显示“母稿已更新，请重新生成排版”。

生成公众号排版时，在最终 HTML 根节点写入：

- `data-wechat-template`：模板文件名；
- `data-canonical-sha256`：标题、摘要和正文的稳定 SHA-256；
- `data-layout-generated-at`：生成时间。

这些元数据只用于一致性判断，不需要数据库新字段。

## 二、平台预览与真实发布输入统一

新增单一的“平台发布源构造器”，输入为内容记录和平台 ID，输出为临时源文件、源格式、内容哈希和用户可见说明。

- 微信公众号：存在且哈希匹配的 `layout_html` 时使用 HTML；不存在时使用标准母稿 HTML，并返回“尚未使用公众号模板”的警告。
- Markdown 平台：使用安全序列化后的 Markdown。
- 纯文本平台：使用共享适配层生成的纯文本。
- 其他 HTML 平台：使用共享适配层生成的净化 HTML。

平台预览和正式发布必须调用同一构造器。发布幂等签名同时包含平台 ID、模式和各平台发布源哈希，因此重新生成公众号模板后不会错误回放旧发布结果。

批量发布为每个平台生成独立快照。现有按任务保存的 Markdown 快照保留用于审计，同时增加平台后缀；微信公众号快照使用 `.html`，其余平台按实际输入使用 `.md`、`.html` 或 `.txt`。

## 三、内容序列化完整性

Markdown 序列化遵循以下规则：

- 只有正文第一个顶层 H1 与文章标题规范化后完全相同时才移除；不同标题必须保留。
- front matter 标题使用可逆 JSON 字符串编码，CLI 解析器同步支持该编码。
- Markdown H1 中的换行转换为空格，Markdown 控制字符转义，防止标题注入正文结构。
- 导入、编辑、预览和发布之间的代码块、表格、链接和非重复 H1 必须往返不丢失。

## 四、发布安全与任务终态

### 批量直接发布确认

“发布中心”的批量直接发布改为两步：

1. 点击“直接发布”只打开确认对话框；
2. 对话框展示文章标题、平台清单、平台数量和“直接发布”模式；用户点击最终确认后才创建不可变 `operationId` 并发送请求。

执行中禁用关闭、Escape 和重复确认。取消不会保存 operationId，也不会调用发布 API。

### 逐平台持久化

发布任务建立后，每个平台完成预检或适配器调用后立即写入 `publish_results`，不再等待整个循环结束。

- 明确成功：`success` 或 `platform_draft`；
- 明确失败且未产生外部副作用：`failed`；
- 适配器抛错或响应无法判断是否已产生副作用：`uncertain`。

只要出现不确定结果，任务终态为 `uncertain`；已经完成的平台结果必须保留。操作日志同步进入 `uncertain`，禁止自动重试，并提示人工核对平台后台。

## 五、导入内容与本地 API 安全边界

### 资源 URL

导入正文中的资源限制如下：

- `img[src]`：仅允许 `http:`、`https:`、受限图片 data URI 和 `/uploads/`；禁止其他相对路径、协议相对地址、反斜杠路径及 `/api/`。
- `a[href]`：允许 `http:`、`https:`、`mailto:`、`tel:`、页内锚点和普通相对链接，但点击时继续使用隔离边界。
- 服务端和浏览器端使用相同规则，避免二次渲染重新放宽。

平台预览改为受 CSRF 保护的 POST；平台列表刷新改为独立 POST。GET 不再启动 CLI 或修改平台数据。

### 请求和字段上限

- 普通 JSON 请求：8 MiB；
- 导入正文与正文更新：5 MiB UTF-8；
- 标题：200 个 Unicode 字符；
- 摘要：1,000 个 Unicode 字符；
- 内容类型：100 个 Unicode 字符；
- 文件名：255 个 Unicode 字符。

显式输入超限返回 413 或 400；从正文自动推导的标题截断到 200 字符。

### 小红书图片下载

小红书发布前下载图片时：

- 单图最大 15 MiB，总图数继续限制为 9；
- 仅接受图片 MIME；
- 15 秒超时；
- 拒绝 localhost、环回、链路本地和私网 IP；
- 重定向后的目标重新校验；
- 成功、失败和异常路径都删除临时目录。

## 六、33 平台适配档案

每个平台必须在共享注册表中声明：

- 输出格式：HTML、Markdown 或纯文本；
- 支持模式：平台草稿、直接发布、仅填充待确认；
- 内容能力：图片、封面、富文本、链接；
- 适配成熟度：`verified`、`format-only` 或 `manual-review`；
- 已核验限制及来源日期；
- 无法自动验证的发布前提示。

当前已确认的抖音标题限制和小红书标题/图片限制继续作为硬规则。没有可靠来源的限制不得猜测；该平台返回“基础格式适配，未核验平台最新限制”的警告，直接发布确认框必须显示该警告。这样 33 个平台都有独立、可维护的档案，同时不把六种格式输出冒充成 33 套深度改写。

平台矩阵测试必须遍历 33 个平台，确认每个平台档案完整、预览与发布使用同一格式和哈希、成熟度提示正确。

## 七、品牌与账号配置

公众号模板不再硬编码“维视智造”及机器视觉描述。账号资料从以下来源读取，优先级从高到低：

1. `PUBLISHER_ACCOUNT_NAME` 与 `PUBLISHER_ACCOUNT_DESCRIPTION` 环境变量；
2. 调用模板渲染时显式传入；
3. 空值。

账号资料为空时删除模板中的账号尾注，不插入占位品牌。

README、界面文案和对外说明统一使用“多平台内容发布工作台 / Multimedia Publisher”。内部 `@weibot/*` 包作用域、CLI 命令和环境变量保留兼容性，并在 README 的兼容说明中集中解释，不作为主标题或产品口径出现。

## 八、持续集成

新增 GitHub Actions 工作流，使用 Node.js 24，在每次 push 和 Pull Request 时执行：

1. 安装依赖；
2. `npm run typecheck`；
3. `npm test`；
4. 检查工作树没有测试生成物；
5. 扫描常见 GitHub token、私钥和实际 Cookie 文件名，允许 `.env.example`。

CI 不读取真实 Cookie、不启动平台登录、不执行真实发布。

## 九、测试与验收

所有行为改动先写失败测试并确认红灯，再实现最小修复。至少覆盖：

- 两标签页旧版本保存返回 409，最新内容不被覆盖；
- 聚焦但未输入不会标记脏状态；
- 正文更新使旧排版失效；
- 微信模板进入预览和发布 HTML 快照；
- 模板变化改变幂等签名；
- 非重复 H1 在发布快照中保留；
- 批量发布取消时无请求，确认时仅一次请求；
- 发布异常产生 `uncertain` 任务和已落库的平台结果；
- `/api/` 图片地址被服务端与客户端共同剔除；
- 平台预览 GET 不再执行，POST 需要 CSRF；
- 标题、摘要、正文和请求体上限；
- 小红书私网 URL、超限图片和异常清理；
- 33 平台档案完整性与成熟度提示；
- 空账号资料不会生成品牌尾注；
- 1440、768、390、320 像素下六个菜单、侧栏收起、导入、预览和两类发布确认无横向溢出；
- 浏览器控制台无产品代码错误。

最终执行完整 `npm test`、`npm run typecheck`、独立临时数据库 API 测试和无真实发布的浏览器验收。通过后提交到现有功能分支并更新 PR #1。
